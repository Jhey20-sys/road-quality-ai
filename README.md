# 🚧 Road Quality Assessment System

A deep-learning system that classifies road surface images into four condition tiers — **good**, **satisfactory**, **poor**, and **very poor** — using three convolutional neural networks (Custom CNN, ResNet18, MobileNetV2). Includes a Streamlit web application for end-user inference.

## 📁 Project Structure

The project lives inside a nested folder. The **outer** `road-quality-ai/` is just a wrapper; the **inner** `road-quality-ai/` is the actual project root where you run all commands.

```text

└── road-quality-ai/                    ← project root (run all commands from HERE)
    ├── src/
    │   ├── config.py                   # Hyperparameters and class names
    │   ├── train.py                    # Trains all three models sequentially
    │   ├── evaluate.py                 # Cross-model evaluation and comparison
    │   ├── app.py                      # Streamlit UI for inference
    │   ├── split_dataset.py            # Splits raw dataset into train/val/test
    │   ├── predict.py                  # CLI prediction utility
    │   └── models/
    │       ├── custom_cnn.py
    │       ├── resnet18.py
    │       └── mobilenetv2.py
    ├── dataset/                        # Raw images organized by class
    ├── dataset_split/                  # Auto-generated train/val/test split
    │   ├── train/
    │   ├── val/
    │   └── test/
    ├── samples_for_prediction/         # Sample test images for the app
    ├── trained_models/                 # Generated by train.py
    │   ├── custom_cnn_best.pth
    │   ├── custom_cnn_final.pth
    │   ├── resnet18_best.pth
    │   ├── resnet18_final.pth
    │   ├── mobilenetv2_best.pth
    │   └── mobilenetv2_final.pth
    ├── evaluation_results/             # Generated by evaluate.py
    │   ├── confusion_matrix_*.png
    │   ├── classification_report_*.txt
    │   ├── model_comparison.png
    │   ├── per_class_recall_comparison.png
    │   └── summary.csv
    ├── venv/                           # Virtual environment (created in Step 1)
    ├── requirements.txt
    └── README.md
```

> 💡 **About the nested folders:** every command in this README assumes your terminal is inside the **inner** `road-quality-ai/` (the one containing `src/`). If your prompt shows a path ending in `\road-quality-ai\road-quality-ai>` you're in the right place. If it ends in just `\road-quality-ai>`, run `cd road-quality-ai` once to step into the inner folder.

## 🔧 Prerequisites

- **Python 3.10 or newer**
- **pip** (comes with Python)
- **(Optional)** A CUDA-capable GPU for faster training. CPU works but will be slow.
- **Disk space:** roughly 1–2 GB for dependencies and trained model checkpoints.

Verify Python is installed:

```bash
python --version
```

You should see something like `Python 3.10.x` or higher.

## 🚀 Step 1 — Setup

### 1.1 Open a terminal in the project root

The project root is the **inner** `road-quality-ai/` (the one containing `src/`).

In VS Code: open the project folder, then press `` Ctrl+` `` to open the integrated terminal — it will start in the project root automatically.

In PowerShell or CMD manually:

```bash
cd C:\Users\USER\Downloads\road-quality-ai\road-quality-ai
```

(Adjust the path if you placed the project somewhere else.)

### 1.2 Create a virtual environment

From the project root:

**Windows (PowerShell or CMD):**

```bash
python -m venv venv
.\venv\Scripts\activate
```

**macOS / Linux:**

```bash
python -m venv venv
source venv/bin/activate
```

You'll know it worked when your terminal prompt shows `(venv)` at the start.

### 1.3 Install dependencies

```bash
pip install -r requirements.txt
```

This installs PyTorch, torchvision, Streamlit, scikit-learn, seaborn, matplotlib, pandas, and Pillow.

### 1.4 (Optional) Enable GPU support

Open `src/config.py` and change:

```python
DEVICE = "cpu"
```

to:

```python
import torch
DEVICE = "cuda" if torch.cuda.is_available() else "cpu"
```

This will use your GPU if PyTorch was installed with CUDA support, and fall back to CPU otherwise. Training all three models on CPU can take hours; on a modest GPU it's typically minutes.

## 🗂️ Step 2 — Prepare the Dataset

### 2.1 Organize raw images

Place your raw images inside `dataset/`, one subfolder per class:

```text
dataset/
├── good/
│   ├── img001.jpg
│   ├── img002.jpg
│   └── ...
├── satisfactory/
├── poor/
└── very_poor/
```

The folder names **must match exactly**: `good`, `satisfactory`, `poor`, `very_poor`. PyTorch's `ImageFolder` assigns class indices alphabetically, so consistent naming matters.

### 2.2 Split into train / val / test

From the project root:

```bash
python src/split_dataset.py
```

This produces a `dataset_split/` folder with three subfolders (`train/`, `val/`, `test/`), each preserving the four class subdirectories. You only need to run this once unless your raw dataset changes.

## 🏋️ Step 3 — Train the Models

This step trains **all three models** (Custom CNN, ResNet18, MobileNetV2) one after another.

```bash
python src/train.py
```

### What happens during training

Each model is trained for the full number of epochs defined in `config.py` (default: 10), with validation accuracy tracked every epoch. The script prints something like:

```text
==================================================
Training: custom_cnn
==================================================
Epoch [1/10] Train Loss: 1.2341 | Val Loss: 1.1023 | Val Acc: 0.5421
Epoch [2/10] Train Loss: 0.9876 | Val Loss: 0.9534 | Val Acc: 0.6234
...
custom_cnn done. Best Val Acc: 0.7821
```

### Training output files

After training completes, you'll have a new `trained_models/` folder at the project root containing **six checkpoint files**:

```text
trained_models/
├── custom_cnn_best.pth
├── custom_cnn_final.pth
├── resnet18_best.pth
├── resnet18_final.pth
├── mobilenetv2_best.pth
└── mobilenetv2_final.pth
```

| File                    | Description                                |
| ----------------------- | ------------------------------------------ |
| `custom_cnn_best.pth`   | Best validation checkpoint for Custom CNN  |
| `custom_cnn_final.pth`  | Last-epoch weights for Custom CNN          |
| `resnet18_best.pth`     | Best validation checkpoint for ResNet18    |
| `resnet18_final.pth`    | Last-epoch weights for ResNet18            |
| `mobilenetv2_best.pth`  | Best validation checkpoint for MobileNetV2 |
| `mobilenetv2_final.pth` | Last-epoch weights for MobileNetV2         |

A final summary table prints all three best validation accuracies side by side.

### Best vs Final checkpoints

`*_best.pth` is overwritten every time the model achieves a new highest validation accuracy during training. `*_final.pth` is saved once at the very last epoch regardless of performance. **Use `_best.pth` for inference and evaluation** — it represents the model at peak generalization. `_final.pth` is mainly a safety net in case the best file gets corrupted, or a starting point for resumed training.

If `_best.pth` is much better than `_final.pth`, the model overfit during the later epochs (train loss kept improving while validation got worse). If they're nearly identical, the model could probably benefit from more training epochs.

### Tips

- If you only want to retrain one model, comment out the others in the `models_to_train` dictionary at the bottom of `train.py`.
- If you run out of GPU memory, lower `BATCH_SIZE` in `config.py`.
- Re-running `train.py` overwrites the previous `.pth` files in `trained_models/`.

## 📊 Step 4 — Evaluate the Models

Once training is complete, run the evaluation script to benchmark all three models on the held-out test set:

```bash
python src/evaluate.py
```

### Evaluation output files

All evaluation artifacts are saved to a new `evaluation_results/` folder at the project root:

```text
evaluation_results/
├── confusion_matrix_custom_cnn.png
├── confusion_matrix_resnet18.png
├── confusion_matrix_mobilenetv2.png
├── classification_report_custom_cnn.txt
├── classification_report_resnet18.txt
├── classification_report_mobilenetv2.txt
├── model_comparison.png
├── per_class_recall_comparison.png
└── summary.csv
```

### What it produces

For each model:

- Test accuracy printed in the terminal
- A confusion matrix saved as `confusion_matrix_<model>.png`
- A full classification report (per-class precision, recall, F1) saved as `classification_report_<model>.txt`
- Highlighted recall for the `very_poor` class (the safety-critical metric)

Cross-model comparison:

- `model_comparison.png` — accuracy / precision / recall / F1 across all three models
- `per_class_recall_comparison.png` — per-class recall to see which model best detects severe damage
- `summary.csv` — tabular summary of all metrics, ready to open in Excel
- A pandas summary table printed to the terminal with the winner for each metric

### Interpreting the results

The most important metric for road maintenance is **recall on `very_poor`**. A high recall means the model rarely misses severely damaged roads (few false negatives). Choose the model with the best balance of overall accuracy and `very_poor` recall for production use.

## 🌐 Step 5 — Launch the Streamlit App

The web app uses **MobileNetV2** by default (best balance of accuracy and speed in our tests). Make sure `trained_models/mobilenetv2_best.pth` exists from Step 3 before launching.

### Run the app

From the project root:

```bash
streamlit run src/app.py
```

> ⚠️ **Important:** Use `streamlit run`, **not** `python src/app.py`. Running it as a plain Python script bypasses the Streamlit runtime and produces `missing ScriptRunContext` warnings with no UI.
>
> 💡 **About the path:** because of the nested folder layout, the absolute path to `app.py` is something like `C:\Users\USER\Downloads\road-quality-ai\road-quality-ai\src\app.py`. The relative form `src/app.py` is cleaner and works as long as you're in the project root (the inner `road-quality-ai/`). If you absolutely need the absolute path, wrap it in quotes: `streamlit run "C:\Users\USER\Downloads\road-quality-ai\road-quality-ai\src\app.py"`.

### Using the app

1. Streamlit opens a browser tab at `http://localhost:8501`.
2. Read the classification legend at the top.
3. Click **📤 Upload road images** and select one or more JPG/PNG files.
4. Each uploaded image previews on the page.
5. Click **🔍 Predict All Images**.
6. For each image you'll see the predicted condition, the confidence percentage, and a colored alert appropriate to the severity:
   - 🥳 Green for **good**
   - ℹ️ Blue for **satisfactory**
   - ⚠️ Yellow for **poor**
   - 🚨 Red for **very poor** (immediate repair required)

### Stopping the app

Press `Ctrl+C` in the terminal where Streamlit is running.

### Switching to a different model

If you'd rather use ResNet18 or the Custom CNN, edit two lines in `src/app.py`:

```python
# Change the import
from models.resnet18 import get_resnet18
# (or) from models.custom_cnn import CustomCNN

# Inside load_model():
WEIGHTS_FILENAME = "resnet18_best.pth"   # or "custom_cnn_best.pth"
# ...
model = get_resnet18(NUM_CLASSES)         # or CustomCNN(NUM_CLASSES)
```

The app's path-walking logic searches for the file inside `trained_models/`, so you don't need to specify the folder. Save and the running Streamlit app will offer to rerun automatically.

## ⚙️ Configuration Reference

All hyperparameters live in `src/config.py`:

| Setting         | Default                                      | What it controls                                                     |
| --------------- | -------------------------------------------- | -------------------------------------------------------------------- |
| `IMAGE_SIZE`    | `224`                                        | Input image dimensions (224×224 matches ImageNet pretrained models)  |
| `BATCH_SIZE`    | `32`                                         | Number of images per training batch. Lower if you hit memory errors. |
| `EPOCHS`        | `10`                                         | Number of full passes through the training set per model             |
| `LEARNING_RATE` | `0.001`                                      | Adam optimizer learning rate                                         |
| `NUM_CLASSES`   | `4`                                          | Number of road condition classes                                     |
| `DEVICE`        | `"cpu"`                                      | Where to run computation. Change to `"cuda"` for GPU.                |
| `CLASS_NAMES`   | `['good','poor','satisfactory','very_poor']` | Class labels in alphabetical order                                   |

## 🔧 Troubleshooting

### FileNotFoundError for mobilenetv2_best.pth

You haven't trained the models yet, or your terminal is in the wrong folder. Make sure your terminal is in the **inner** `road-quality-ai/` (the one containing `src/`), then run `python src/train.py`. The weights will be saved to `trained_models/mobilenetv2_best.pth` automatically.

If you have older `.pth` files sitting directly at the project root from a previous version of this project, the app will still find and use them via its fallback path-walking logic — no need to delete them. Re-running `train.py` will create the new `trained_models/` folder going forward.

### Missing ScriptRunContext warnings when launching the app

You ran `python src/app.py` instead of `streamlit run src/app.py`. Use the latter.

### "No such file or directory" errors when running scripts

Your terminal is most likely in the wrong folder (the outer wrapper instead of the inner project root). Run `cd road-quality-ai` once to step in, then re-run the command. To verify you're in the right place, list the directory contents — you should see `src/`, `dataset/`, `requirements.txt`, and `README.md` at the top level.

### StreamlitInvalidColumnSpecError or st.columns(0) error

This was caused by uploading then removing images while the app was rendering. The current `app.py` guards against this — make sure you're using the latest version.

### Pylance cannot resolve models.mobilenetv2

The `models/mobilenetv2.py` file is missing. Create it with this content:

```python
import torch.nn as nn
from torchvision import models

def get_mobilenetv2(num_classes, pretrained=True):
    weights = models.MobileNet_V2_Weights.DEFAULT if pretrained else None
    model = models.mobilenet_v2(weights=weights)
    in_features = model.classifier[1].in_features
    model.classifier[1] = nn.Linear(in_features, num_classes)
    return model
```

### Training is extremely slow

You're probably training on CPU. See Step 1.4 above for enabling GPU.

### Out-of-memory error during training

Lower `BATCH_SIZE` in `config.py` (try 16, then 8). Also make sure no other GPU-using applications are running.

### The app shows wrong predictions

Verify that `CLASS_NAMES` in `config.py` is in alphabetical order — PyTorch's `ImageFolder` assigns indices alphabetically, so the order matters. The default `['good', 'poor', 'satisfactory', 'very_poor']` is correct.
